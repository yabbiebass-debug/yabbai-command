# Findings — 17 August 2026

Written so the reasoning survives. Code shows *what*; this is the *why*, including
the parts that were wrong and how they were found. If you are picking this up
cold — a person, or a model with no memory of the session — start here.

---

## 1. The Wallet Standard handshake was broken. All of it.

**Severity: high. This silently disabled wallet detection across the whole app.**

`lib/wallets.js` announced the app to wallet extensions like this:

```js
window.dispatchEvent(new Event(APP_READY));      // wrong
```

A bare `Event` has no `detail`. The Wallet Standard requires a `CustomEvent`
whose `detail` is the API object, because every extension destructures it the
moment it arrives:

```js
({ register }) => register(theirWallet)
```

With `detail` undefined, that destructure throws **inside the extension's own
injected script**. Which is why the console filled with:

```
Cannot destructure property 'register' of 'undefined'
  at chrome-extension://…/solana.js
  at chrome-extension://…/inpage.js
```

Traced to the extensions, not to us — so it read like someone else's bug. It
wasn't.

**Consequence:** every Wallet Standard extension threw, registered nothing, and
`_registry` stayed empty. Detection then fell through to sniffing `window.solana`
globals, so **only legacy extension builds were ever found**. MetaMask, Backpack
and modern Phantom register exclusively via the standard — none of them were
detected, ever. That affects the treasury sweep and the buyback panel, not just
the faucet.

Commits `4d73a18` and `c3b2d02` were previous attempts at this symptom. They
treated late registration; the handshake itself was the cause.

**Fix:** publish a real API object and hand it to wallets that ask.

```js
const api = { register: (...wallets) => { wallets.forEach(addWallet); return () => {}; } };
window.dispatchEvent(new CustomEvent(APP_READY, { detail: api }));
```

Also handle the spec shape of the inbound event: `detail` is a *callback* the
wallet wants passed the API, not the wallet itself. The old object shape is kept
as a fallback for older builds.

**How to verify without installing anything** — impersonate an extension in the
console:

```js
let api = null;
window.dispatchEvent(new CustomEvent('wallet-standard:register-wallet', {
  detail: (received) => { api = received; }
}));
typeof api?.register === 'function'   // must be true
```

**Do not poll `detectWallets()` on an interval.** It drives this handshake, so a
1s poll re-runs every installed extension's registration handler once a second
for the life of the tab. Bounded timeouts only.

## 2. The site was invisible to search, and the console was not

`public/index.html` shipped an empty `<div id="root">` and nothing else. Google
renders JS on a delayed second pass; Telegram, Discord, Bing and every SEO tool
do not render at all. They saw a blank page.

Added: canonical, Open Graph, Twitter card, JSON-LD with the real mint, a crawler
fallback inside `#root` (React replaces it on mount), favicon, `robots.txt`,
`sitemap.xml`.

**The canonical tag is the anti-impersonation one.** Scrapers copy markup
wholesale, canonical included, so a lookalike domain ends up carrying a tag
pointing back here — Google credits this origin and demotes the copy.

### The default direction is deliberate

`index.html` ships `noindex, nofollow`. `scripts/seo.js` clears it **only** for
the holders build. Both builds share `public/`, so per-target crawler rules
cannot live in the source tree — they are written post-build once
`REACT_APP_BUILD_TARGET` is known.

If that step is skipped or fails, the result is a public page that does not get
listed. Recoverable. The opposite default would put the treasury and withdrawal
screens into a search index, which cannot be undone once crawled.

**The console was previously indexable.** It is now `Disallow: /` plus `noindex`.

### Build chaining gotcha

`craco build && node scripts/seo.js` broke when the wallet import pulled in
`@solana` packages with missing `.ts` source maps — the warnings made craco exit
non-zero, the `&&` stopped, and the SEO step silently never ran. Fixed with
`GENERATE_SOURCEMAP=false`, which also stops shipping source to the public.

Note `cross-env` applies to one command only; it is repeated after the `&&`.

## 3. Faucet: a queue, not a hot wallet

`backend/faucet.py` stores signed intent. It never holds a key.

The obvious build funds a keypair on the server and pays instantly. That would be
the first private key this app has ever held, and the README's strongest claim
would stop being true. A server key is reachable by anything that can read the
filesystem or the environment — and a faucet exists so strangers can poke it.

So: claimer signs a message (proving address ownership, moving nothing), the
claim queues, the operator pays the batch from their own wallet, the payout
signature is recorded. Worst case is a junk queue, which can be truncated. A
drained wallet cannot be undone.

**Sybil resistance is not claimed and should never be advertised.** One claim per
address falls to a thousand addresses. Every mitigation falls nearly as easily.
The real control is the operator seeing the batch before paying, plus the cap.

**The public build now contains wallet code** — `signMessage` only.
`signAndSendTransaction` is *not* imported and must not be; verified absent from
the built bundle. A signed message authorises no transfer. The moment that build
can submit a transaction, the isolation argument is void.

## 4. A faucet is counterproductive before graduation

Measured 17 Aug: **0.23% to graduation**, 202.3 / 1200 SOL, ~998 SOL (~$75.5k)
remaining. 24h: 8 trades, 8 buys, 0 sells.

Free tokens get sold. On a bonding curve, selling does not merely add supply — it
pulls SOL back *out of the curve*, lowering market cap and moving graduation
**further away**. A thousand free-token wallets is a thousand potential first
sellers against a curve with zero sells so far.

**Keep `FAUCET_ENABLED=false` until after graduation.** Post-graduation there is
a real Meteora pool and the dynamics change. The code is finished and tested; it
is the timing that is wrong, not the build.

## 5. Stablecoin reserve maths (`../yabbai-stablecoin`)

14/14 tests, no network required: `node src/invariant-test.js`

The one rule: `circulating x peg <= USD actually held in reserve`.

- **The peg number is arbitrary.** $1.50, $24.70 and $420 are the same economics
  in different units. It sets only how much collateral each token requires, and
  the two move in lockstep. $420 does not make anyone richer; it makes each token
  a larger claim on the same pile, so you issue proportionally fewer.
  `PEG_CENTS` is configurable and tested at all three.
- **Rounding must always favour the reserve.** Minting rounds tokens down,
  redeeming rounds the owed USD up. The other direction leaks a fraction of a
  cent per operation, and that loop gets run a million times. Integer/BigInt
  throughout — a drifting peg is a broken peg.
- **Volatile collateral is the real failure mode.** Test 5 demonstrates it:
  nothing is minted wrongly, the collateral simply becomes worth less than the
  promise written against it. This is why real issuers hold boring assets.
- The devnet script's mint authority is a keypair on disk, so the operator can
  mint unbacked. Making the rule real requires a PDA owned by an on-chain program
  that checks the reserve inside the minting transaction. That is step 2 and it
  needs Rust.

## 6. Boundaries worth not rediscovering

- **Devnet cannot bridge to mainnet.** Devnet SOL is infinite; a bridge would be
  an infinite money printer. The networks share no ledger and never will. Anyone
  offering such a bridge is running a scam.
- **No code sets a market price.** Price is what people pay. Recorded price
  17 Aug: `$0.0000153108` — $2/token is ~130,000x. The only mechanisms that move
  a number to a target are real capital (manipulation, if it is your own token)
  or faking the display (fraud, and the thing this repo already removed once).
- **Tokens sold to people expecting a return are financial products** under the
  Corporations Act. AFSL plus disclosure. ASIC prosecutes unlicensed offers and
  the exposure is personal.
- **Other people's names cannot go on a token.** Implying endorsement is
  misleading conduct under the ACL plus passing off. Your own name is free.
- **A token cannot be a prescription pathway.** Medicinal cannabis in Australia
  runs through TGA Authorised Prescriber / SAS-B with real doctors. Anything
  implying hold-token-get-script is a supply or advice pathway without
  authorisation, and it lands on whoever's name is on the project. A legalisation
  *advocacy* theme is political speech and carries none of that.
- **Order before anyone else's money:** on-chain program, audit, legal advice on
  AFSL, real reserves. Then investors. Not before.

## 9. Fixed after the above was written

**Inline script blocked by CSP.** `index.html` carried the DataCloneError
handler inline, while the CSP is `script-src 'self'` with no `unsafe-inline` and
no nonce. The browser refused it on every deployed page — the handler had never
run in production since the CSP was tightened. It worked locally only because no
CSP header is served there, which is precisely why it went unnoticed for so long.

Moved to `public/error-shim.js` and loaded with `src`, satisfying `'self'`. The
alternative — adding `'unsafe-inline'` — would re-permit every inline script on
the page and surrender most of the CSP's value to silence one warning.

Verified in the running app: shim tag present, zero app inline scripts remaining.
`application/ld+json` is excluded from that count deliberately; it is a data
block, not executable, and is not subject to `script-src`.

**Note for future changes to `public/index.html`:** the CRA dev server does not
watch that file. Editing it appears to do nothing until the dev server is
restarted, which reads as a broken change. Restart before concluding anything.

**Faucet payout screen.** `pages/FaucetPayout.js`, routed at `/faucet` inside
`ProtectedRoute`. Verified present in the command build and absent from the
holders build, along with `faucet/pending` and `signAndSendTransaction`.

It is a worksheet, not a one-click payout, and that is deliberate. Building a
batch SPL transfer in the browser needs `@solana/spl-token`, which this frontend
does not ship — adding a dependency for the express purpose of moving real
tokens is not a change to make quickly. So: read the verified batch, copy
`address,amount` rows, send from the wallet you already trust, paste the
signature back. Marking paid writes history; it moves nothing. A wrong signature
there means the ledger disagrees with the chain, which is worse than an unpaid
claim.

One-click payout is the upgrade whenever it is wanted, and it is a deliberate
decision rather than an omission.

**Auth surface widened by three routes — deliberately.** `tests/test_auth_surface.py`
failed on the faucet, which is the tripwire working: it exists because a previous
version of this project was publicly reachable and got swept.

Added to `PUBLIC` after checking each one:

```
GET  /api/faucet/status    counts and cap only; no addresses, no operator state
POST /api/faucet/nonce     anti-replay nonce, public by design, 10/min
POST /api/faucet/claim     ed25519-verified, deduped, capped, 5/min
```

They must be anonymous — the claimers are strangers with a wallet and no account,
which is what a faucet is. What makes that acceptable is that **none of them can
move value**: the server holds no key, and the worst reachable outcome is a queue
of junk, which can be truncated. That is a different failure class from the one
that caused the sweep.

The rule to keep: if a faucet route ever gains the ability to sign, transfer or
authorise, it no longer belongs on that list. Re-run the test after any change to
`faucet.py`.

**Full suite green as of this session:** auth surface (75 routes, 6 anonymous),
wallet auth 6/6, performance 6/6, reserve invariants 14/14.

**Deploy config, two real bugs found and fixed:**

- `render.yaml` served **no CSP at all**, while `netlify.toml` had a tight one —
  the same bundle was protected completely differently depending on host. Policy
  mirrored into both static services.
- `connect-src` listed `https://yabbai.network` but **not** `https://api.yabbai.network`.
  CSP host matching has no implicit subdomain wildcard, and `REACT_APP_BACKEND_URL`
  points at that exact host, so every API call would have been blocked. It surfaces
  as a CSP violation rather than a network error, which sends you looking in the
  wrong place entirely. Fixed in `render.yaml` and `netlify.toml`.

**Still blocking deploy:** all three Render services build from `main`, and the
work is on `feat/real-mainnet-data`, six commits ahead. Deploying without merging
ships the pre-session app.
